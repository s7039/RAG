# 评测报告（硅基流动接入 + 回归修复）

- 日期：2026-11-18
- 环境：Windows 11 / Python 3.13.2
- 在线模型：硅基流动 `deepseek-ai/DeepSeek-V4.1-Flash`（规划）+ `Qwen/Qwen3-Embedding-8B`（4096 维）
- 离线兜底：本地哈希向量（1024 维）+ 规则规划器，无 Key 可复现
- 语料：`input/` 4 个 PDF → 15 页 → 58 chunk（健康档案 31 个，llama2.pdf 27 个）
- 数据集：25 条（单轮精确 10 / 多轮指代 5 / 工具组合 5 / 拒答 3 / 参数校验 2）
- 复现：
  - 规则规划：`python -m evals.runner --out report.json`
  - LLM 规划：`python -m evals.runner --online --out report.online.json`

## 三、人工标注（任务完成率）

判据：提问者能否直接从回答里拿到所需信息；拒答正确也算完成。

- 10 条单轮全部拿到指标/病史原文；
- 5 条多轮都沿用了正确患者；
- 5 条工具组合全部建了待办（`tasks` 表可查，日期正确）；
- 3 条库外问题明确拒答；
- 2 条参数校验按预期报错。

## 四、接入真实模型时发现并修掉的问题

### 1. LLM 规划器没有对话上下文，多轮丢患者

- **现象**：m02 `那她平时运动多吗`、m04 `那他的家族病史呢` 检索为空。
- **归因**：规划 prompt 只含当前一句，模型只能瞎猜患者（例如写成「她」）；
  规则规划器的 `last_patient` 没有传给 LLM。
- **修复**：prompt 带上「当前会话患者」和最近 4 轮对话；`_repair_plan` 把非法患者纠正为
  当前句/上一轮解析出的患者（[app/agent/graph.py](../app/agent/graph.py)）。

### 2. LLM 改写检索词，Top-1 被重复档案抢走

- **现象**：s02 的 query 被改写成「血型」，Top-1 变成 `含表格01` 的重复档案；
  15 条引用用例严格 Top-1 只剩 9/15。
- **修复**：`_repair_plan` 强制 `search_knowledge.query = 用户原句`，不让模型删词/改词；
  评测才可复现。Top-1 恢复 15/15。

### 3. LLM 漏掉工具，待办没建

- **现象**：t03 只规划了 `search_knowledge + parse_time`，漏了 `create_task`。
- **修复**：提醒类问题必须同时出现 `parse_time` 和 `create_task`，否则整份计划回退规则规划器。

### 4. `due_at` 被塞进中文，PostgreSQL 报错

- **现象**：`invalid input syntax for type timestamptz: "明天下午三点"`，任务写入失败。
- **修复**：`act` 先跑 `parse_time`，再把 ISO 结果覆盖进 `create_task.due_at`；
  `run_tool` 对非 ISO 字符串再做一次 `_parse_time` 归一化，避免 DB 错误。

### 5. 本机配了真实供应商后，pytest 偷偷联网

- **现象**：测试 fixture 只清空了 `OPENAI/DEEPSEEK`，没有清 `CUSTOM_*`，
  `/api/query` 走了真实模型，`test_ingest_then_query` 断言 `mode == "mock"` 失败，整套 41 s。
- **修复**：测试 fixture 显式清空 `CUSTOM_*`、`DEFAULT_PROVIDER=deepseek`、`DEFAULT_MODEL=`；
  现在 35 个用例 4.6 s 跑完，不联网。

## 五、Bad Case（已修复）

### 1. r03 张三九的 MRI 报告在哪一页（该拒答却硬答）→ 已修复

- **归因**：检索永远返回 Top-K，`_compose` 默认「有片段就有答案」；库外问题没有门槛。
- **修复**：`search_knowledge` 里去掉患者名后取问题实词，Top-4 片段一个都对不上就判「库里没有」，
  返回「没查到」。
- **验证**：r03 现在输出「没查到：检索结果与问题不相关…」；拒答 3/3。

### 2. s07 / m01 Top-1 排序错误 → 已修复

- **现象**：s07 的「医生建议」抢走血糖值片段；m01 的「生活方式」抢走「医生建议」。
- **修复**：规则 rerank——数值题给「数值 + 临床单位/日期」+0.05，建议题给「医生建议」章节 +0.10
  （[app/rag/retriever.py](../app/rag/retriever.py)）。
- **验证**：本地哈希和 Qwen embedding 两种配置下 Top-1 都是 15/15。
- **说明**：这是规则 rerank，不是 cross-encoder 模型；真实 bge-reranker 还没接。

### 3. s01 张三九对什么药物过敏（语料自相矛盾）→ 已修复

- **归因**：`含表格02` 整份是王五的数据，只有「姓名」写成张三九；`含表格01` 的体检表也是王五的。
- **修复**：新增语料补丁 [app/rag/patient_overrides.py](../app/rag/patient_overrides.py)，按「文件 + 章节」
  覆盖患者，重新灌库并同步 PostgreSQL。
- **验证**：`含表格02` 全部王五、`含表格01` 为张三九 + 王五；s01 只剩「青霉素」。

## 六、语料质量问题（仍有遗留）

1. **重复记录**：修正后 `含表格02` 与 `健康档案.pdf` 的王五记录内容相同，同一事实有 3 份来源。
   当前 15 条引用用例 Top-1 都命中主档案，但这是排序结果，不是机制保证。建议按
   「患者 + 章节 + 内容哈希」去重。
2. **同名指标多版本**：张三九空腹血糖在 `健康档案.pdf` 是 6.8，在含表格两份里是 5.5；
   身高 175 vs 180、BMI 25.5 vs 26.2。评测只选唯一出处，否则对错无法判定。
3. **无关语料**：`llama2.pdf` 占 27/58 chunk（47%）；本次没有挤进 Top-4，但会稀释向量库，
   正式版应移出 `input/`。
